# 사용자 요청

이제 supabase  MCP를 연결했습니다.
이제 데이터베이스를(db) 수파베이스 MCP를 이용하여  DB를 만들어서 넣어주세요. 이때 데이터베이스 테이블의 이름은 앞글자를 따서 "gn_"로 테이블을 만들어서 연동해주세요.
앞으로 만들 소설은 모두 여기에도 연동할 예정이에요. . 제가 소설을 만들면 자동으로 여기 DB에 쌓이고, 제가 모바일 핸드폰으로 볼 수 있어야 돼요.
아직 앱을 배포하지는 않았지만, DB 연동만이라도 하려고 해요. 아마 배포는 wrangler mcp 로 할거에요 ( cloudflare worker ) wrangler 로그인을 했으니, 혹시 배포까지 할 수 있으면 배포까지 진행해주세요.
그러면 제가 모바일, 그리고 맥북으로 접속해서 테스트해볼게요.

## 확인한 상태

- Supabase MCP는 fresh-mint, wmp-clever-lemon 두 프로젝트를 반환한다. 어느 프로젝트에도 gn_ 테이블이 없다.
- 대상 프로젝트 선택 질문을 보냈으나 아직 답변을 받지 못했다. 임의 프로젝트에 쓰지 않는다.
- Wrangler MCP는 도구 목록에 없지만 CLI는 로그인돼 있다. gen-novel-reader Worker는 아직 존재하지 않는다.

## 진행 결과

- gn_books, gn_episodes, gn_episode_revisions, gn_sync_state, gn_sync_credentials 및 토큰 검증 RPC migration 작성.
- 독자는 공개 원고만 읽고 직접 쓰기는 불가. 소설 전용 동기화 토큰은 전체 프로젝트 service_role 권한을 사용하지 않는다.
- main push 기반 GitHub 자동 동기화, 새 회차를 재배포 없이 읽는 URL, Worker 런타임 API 구현.
- 실제 데이터 소스 선택 전에는 workflow variable GN_SYNC_ENABLED가 없어 동기화 job이 건너뛰어진다.
- PostgreSQL 로컬 엔진에서 RLS/토큰/재시도/원자성/이력 테스트, Worker mock 등 11개 테스트 통과.
- Next.js build 및 Wrangler dry-run 통과. 실제 원격 migration·적재·secret 설정·배포는 아직 미실행.
- 이후 절차는 docs/supabase-sync.md. 사용자 프로젝트 선택을 받으면 연결 및 배포를 이어서 완료한다.
