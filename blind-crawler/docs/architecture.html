알림은 탭이,
기억은 Mac이.

02 / ANDROID LIFECYCLE

화면과 서비스는 다른 역할입니다.

MainActivity는 설정 창이고 BlindListener는 Android가 연결하는 알림 서비스입니다. 창을 닫는 것과 앱을 강제 종료하는 것은 다릅니다.

화면을 꺼도 됨

홈 이동 · 화면 잠금

서비스가 시스템에 연결되어 있다면 알림을 감지합니다. 블라인드 앱도 계속 화면에 띄워 둘 필요는 없습니다.

다시 열어야 할 수 있음

강제 종료 · 절전 제한

설정에서 강제 종료하면 백그라운드 동작이 중지될 수 있습니다. Samsung 절전·초절전 앱 분류도 확인하세요.

실행에 USB 불필요

전원 · Wi-Fi 유지

MacBook의 ADB는 설정에만 사용했습니다. 태블릿은 집 Wi-Fi로 Mac mini에 직접 알림을 전송합니다.

MainActivity: 설정·상태 확인≠BlindListener: 알림 이벤트→Queue + UploadJob: 전달·재시도
최근 앱에서 카드를 지워도 되나요?

최근 앱 카드 제거는 설정의 강제 종료와 다릅니다. 하지만 제조사의 별도 절전 정책에 따라 결과가 달라질 수 있어 장기 수신을 보장하지는 않습니다. 안정적인 운영을 위해 두 앱이 절전·초절전 목록에 들어가지 않도록 확인하세요.

태블릿을 재부팅하면 어떻게 되나요?

BOOT_COMPLETED 수신 시 서비스 재연결과 전송 작업을 요청합니다. 부팅·잠금 해제 이후 실제 알림 수신을 확인해야 합니다. OS가 즉시 또는 영구적으로 연결을 유지한다는 보장은 없습니다.

인터넷이나 Mac mini가 잠시 꺼지면요?

이미 감지해 큐에 저장한 알림은 기기에 남습니다. 전송 실패 시 JobScheduler가 네트워크 조건과 backoff를 고려해 재시도합니다. 처음 예약하는 최소 1초와 backoff 30초는 정확한 실행 보장이 아닙니다. 서비스가 실행되지 않아 아예 감지하지 못한 알림까지 모두 복원할 수 있는 것은 아닙니다.

기기 확인: Android 13 / API 33. 일반 백그라운드 실행은 기본 허용으로 조회됐습니다. Samsung의 모든 절전 예외나 장시간 화면 꺼짐 상태까지 검증했다는 뜻은 아닙니다.

03 / APPEND-ONLY SNAPSHOTS

펑은 새 버전, 예전 글은 그대로.

아래 버튼으로 가상의 글 상태를 바꾸고, 왼쪽 보관본을 선택해 보세요. 설명용 예제이며 실제 서버나 원문은 변경하지 않습니다.

주말에 가볼 만한 곳

게시글 ID + 전체 파싱 결과의 SHA-256이 같으면 중복 버전을 생략합니다. 본문뿐 아니라 댓글이나 확보 상태가 달라져도 새 버전이 생길 수 있습니다.
처음 수집한 내용만 보존할 수 있습니다. 첫 수집 전에 이미 수정·삭제된 내용은 복원할 수 없습니다. 404는 접근 불가 관찰 기록으로 남기고 이전 스냅샷을 지우지 않습니다.

구성현재 동작
태블릿 queue서버 접수 전까지 알림 보유. 알림 감지 → 로컬 저장 → 전송 → 2xx 후 제거.
Mac mini SQLiteposts는 최근 상태, snapshots는 이전 내용, observations는 접근 결과, notifications는 알림을 저장합니다. jobs와 comment_jobs는 별도 대기열입니다.
검색새 스냅샷마다 검색 문서를 추가합니다. FTS5 테이블을 쓰지만 현재 질의는 LIKE 부분 검색으로, 옛 버전의 본문·댓글도 찾습니다.
수집·재방문목록 기본 10분, 요청 시작 사이 기본 5초. 최초 발견 후 1시간 이내 10분 / 하루 이내 30분 / 이후 6시간 재방문. 7일 경과 후 성공 처리한 작업은 재방문 종료, 보관본은 유지.

백업시작 시와 날짜 변경 후 SQLite backup API + integrity_check. 요일별 7개 순환. 같은 SSD에 있어 SSD 자체 고장 대비는 별도 장치 복제가 필요합니다.

05 / BOUNDARIES
무엇을 할 수 있고, 무엇은 아직 못 하나요?
현재 구현
알림과 공개 웹 연결
제목·미리보기·공개 문자열에 노출된 URL을 전달합니다. URL이 없으면 저장된 글 제목에 정확히 맞는 단일 후보만 연결합니다.
현재 제약
댓글 더보기의 403
자동 브라우저가 HTTP 403을 받은 상태가 확인됐습니다. 해당 댓글 작업자는 1시간 중단하고, 본문 작업자는 별도로 계속 진행합니다. 댓글 전체 보존은 보장하지 않습니다.
구현하지 않은 기능
앱 자동 클릭 · 화면 추출
공식 앱을 자동으로 열어 본문을 읽지 않습니다. 이미지·영상·스크린샷·OCR·비공개 API나 인증 추출도 현재 경로에 없습니다.
집 안에서 로그인 없이 보는 것은 어떤 의미인가요?
허용된 LAN에서 접속 가능한 사람은 보관함을 읽을 수 있습니다. 기기 키는 알림 전송 검사용이며 사용자별 열람 권한은 아닙니다. 설정 API도 LAN 안에서 키를 표시합니다. HTTP는 TLS 암호화가 없으므로 신뢰하는 집 네트워크를 전제로 하며 외부 Tunnel 연결용 구성이 아닙니다.
알림에 URL이 없으면 정확히 무엇을 비교하나요?
알림 제목·미리보기 전체·미리보기 첫 줄을 공백 정규화한 뒤 5자 이상인 문자열을 글 제목과 정확히 비교합니다. 후보 ID가 하나일 때만 연결합니다. 이후 본문 수집이 성공할 때 최근 미연결 알림 100개를 재검사합니다. 이 경로는 기존 jobs 행의 우선순위를 올리므로 이미 재방문이 끝난 오래된 작업을 새로 만들지는 않습니다.
‘원문’과 ‘확보 완료’는 어떻게 해석해야 하나요?
원문은 작성 직후 내용이 아니라 처음 확보한 버전입니다. 댓글은 확보 개수·사이트의 표시 수·남은 더보기를 기준으로 상태를 표시합니다. 개수가 맞아도 수집 이전에 사라진 모든 댓글을 확보했다는 의미는 아닙니다. HTTP 오류도 작성자가 삭제했다는 확정 증거로 취급하지 않습니다.
